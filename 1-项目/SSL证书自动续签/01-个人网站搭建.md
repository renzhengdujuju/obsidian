# 个人网站搭建全流程实战：从零到 HTTPS 全链路打通（renzhengdejuju.online）

**项目背景**：从零开始搭建一个可以被公网访问的个人网站（在线考试系统前端），部署页面并实现全站 HTTPS 加密。

> 📍 **本文定位**：SSL 证书自动续签项目的**前传（第 0 篇）**——先有网站和 90 天免费证书，才有后面的续签需求。后续阅读顺序：背景原理 → 方案手册 → 实战记录（详见 [[实习总览]]）。

> 🎯 **最终成果先看**：浏览器打开 `https://renzhengdejuju.online`，地址栏带小锁，在线考试系统页面正常显示（见文末截图）。
>
> ⚠️ **这条路上有个关键弯路**：第一个域名 `renzhengdeju.online`（少个 ju）注册后，证书 DNS 验证怎么都过不去；换注册 `renzhengdejuju.online` 后一次通过。全文会把这个弯路讲清楚。

---

## 🗺️ 全链路总览

```
① 购买 ECS 云服务器（上海）
② 配置安全组：放行 80 / 443 端口
③ 注册域名 + 实名认证（第一个域名 renzhengdeju.online）
④ 域名解析：把域名指向服务器公网 IP
⑤ 远程连接服务器
⑥ 部署 Web 服务：装 Nginx、上传网页（HTTP 先跑通）
⑦ 申请免费 SSL 证书：第一个域名验证卡死 → 换 renzhengdejuju.online → 签发成功
⑧ WinSCP 上传证书和密钥 → Nginx 配置 HTTPS，全链路打通 🎉
⑨ ICP 备案（合规收尾，审核期间网站可能被阻断）
⑩ 长期维护：证书续期、域名续费、常见故障
```

## 第 2 步：配置安全组（放行 80 / 443）

**为什么要做这步**：系统默认创建的安全组里只有 ICMP、远程桌面（3389）和 SSH（22），没有网站要用的 80（HTTP）和 443（HTTPS）。不放行，外面就访问不到你的网站。

![[Pasted image 20261104155929.png]]
> 图：系统默认安全组详情——只有 3 条规则，没有任何网站端口

操作路径：阿里云控制台 → **云服务器 ECS** → 左侧 **安全组** → 创建安全组（或对已有安全组"管理规则"）→ **入方向**添加规则：

- 协议类型：**自定义 TCP**
- 端口范围：**80/80**，授权对象：**0.0.0.0/0**（允许所有人访问）
- 再加一条 **443/443**，同样 0.0.0.0/0
- 22（SSH）保留，供远程连接用

![[Pasted image 20261104155034.png]]
> 图：创建安全组时的规则配置——入方向已放行 HTTP(80)、HTTPS(443)，SSH(22) 仅对特定 IP 放行

## 第 4 步：域名解析（把域名指向服务器 IP）

**原理一句话**：解析 = 在 DNS"电话簿"里登记"这个域名对应哪台机器的 IP"。原理详见 [[02-从域名验证到证书认证-完整闭环梳理|背景文档]]。

1. 进入**云解析 DNS** 控制台 → 公网权威解析 → **添加域名**（把域名加进解析列表）。

![[Pasted image 20261104155519.png]]
> 图：云解析 DNS 添加域名弹窗

2. 用"**快速添加解析**"最省事：选"将网站域名解析到服务器 IPv4 地址"，勾选 `@`（主域名）和 `www` 两条，记录值填 ECS **公网 IP** `8.159.145.12`。两个域名都用同样方法各做一遍。

![[Pasted image 20261104160056.png]]
> 图：快速添加解析——@ 和 www 两条 A 记录一起生成，指向 8.159.145.12（这前面都是对的，只是后面ssl证书指定的网址为renzhengdeju.online导致无法验证这个域名在这里配置的DNS，所以后续在ssl重新购买证书，把名字改为renzhengdejuju.online证书立即就下发了）

3. 添加完成后，解析记录列表里就有两条 A 记录（`@` 和 `www`）。第三条 `_dnsauth` 的 TXT 记录是后面第 7 步申请证书时才加的。

![[Pasted image 20261104160656.png]]
> 图：renzhengdejuju.online 的解析设置全景——@ / www 两条 A 记录 + 证书验证用的 _dnsauth TXT，顶部绿字"域名的DNS信息全部配置正确"

4. 验证是否生效：本地 CMD 执行

```bash
nslookup renzhengdejuju.online
```

返回 `8.159.145.12` 就说明解析已生效。

## 第 6 步：部署 Web 服务（HTTP 先跑通）

### 6.1 先看到第一个页面

80 端口通了之后，手机浏览器访问域名，第一次看到的是系统预装 Apache 的默认测试页——**这说明"域名 → 解析 → 服务器 → Web 服务"整条路已经通了**，只是显示的还不是自己的页面，而且地址栏是"不安全"（还没有 HTTPS）。

![[Pasted image 20261104160145.png|238]]
> 图：手机访问 renzhengdejuju.online，显示 Apache httpd 默认测试页，地址栏"不安全"——链路已通，内容待换

### 6.2 安装 Nginx

```bash
yum install nginx -y
systemctl start nginx
systemctl enable nginx
```

**踩坑记录：端口冲突（80 被 Apache 占用）**

- **问题**：`systemctl status nginx` 发现 Nginx 没起来，`netstat -tlnp | grep :80` 发现 80 端口被 `httpd`（Apache）占用。
- **解决**：停掉并禁用 Apache，再启动 Nginx。

```bash
systemctl stop httpd
systemctl disable httpd
systemctl restart nginx
```

验证：确认此时只有 Nginx 在监听 80 端口。

![[Pasted image 20261104160217.png]]
> 图：终端排查输出——Nginx 1.24.0 已安装并运行（master + 2 worker），监听 80（IPv4+IPv6），Apache 未安装未运行

### 6.3 上传自己的网页文件

1. 本地写好 `index.html`（在线考试系统前端页面）及相关 CSS/JS。
2. 用 **WinSCP**(提前下好桌面应用)上传（SFTP 协议，端口 22，root 账号），把文件拖进 Nginx 默认网站目录：`/usr/share/nginx/html/`，覆盖原来的默认页。

![[Pasted image 20261104160239.png]]
> 图：WinSCP 图形化传输步骤——SFTP / 22 端口 / root，目标目录 /usr/share/nginx/html/

上传完成后浏览器再访问域名，看到的就是**自己的在线考试页面**了（此时还是 http + "不安全"，下一步上 HTTPS）。

### 7.2 填写申请信息（联系人）

申请证书时要填写联系人（姓名、邮箱、手机号；OV/EV 证书才需要身份证号），用于接收 CA 的通知。

![[Pasted image 20261104160625.png]]
> 图：新建联系人弹窗（个人信息已打码）——手机/邮箱必须能正常接收验证信息，机器人不用写

### 7.3 第一次申请：卡死在 DNS 验证（第一个域名 renzhengdeju.online）

申请提交后，CA 要求做 **DNS 验证**：往域名解析里加一条 TXT 记录（主机记录 `_dnsauth`），CA 查到记录值才签发。

**踩坑记录 2：DNS 验证卡死（ERR_EMPTY_RESPONSE / "未检测到DNS记录值"）**

- **问题现象**：在证书申请页面添加了 `TXT` 记录后，点击"验证"一直提示"未检测到DNS记录值"。
- **排查过程**：
    - 本地 CMD 执行 `ipconfig /flushdns` 刷新缓存（需要管理员权限）；
    - 使用 `nslookup -type=TXT _dnsauth.renzhengdeju.online 223.5.5.5` 指定阿里云公共 DNS 查询，一直报 `Non-existent domain`；
    - 使用阿里云网络拨测工具，发现存在前端 Bug（自动拼错前缀 `undefined.`）。
- **各种办法都试过后依然卡死**——这条验证记录在这个域名上就是查不到。

![[Pasted image 20261104160642.png]]
> 图：证书申请的 DNS 验证弹窗——renzhengdeju.online 的 TXT 记录 `_dnsauth` + 记录值，下方红字"未检测到DNS记录值"就是卡死时的状态

**最终决策**：放弃在卡死的旧订单上死磕，**换一个域名重来**——重新注册了 `renzhengdejuju.online`，解析、申请一条龙重新走。

### 7.4 第二次申请：换 renzhengdejuju.online，一次通过

给新域名 `renzhengdejuju.online` + `www` 重新申请证书，同样加 `_dnsauth` TXT 验证记录——这次解析状态直接变绿："域名的DNS信息全部配置正确"。


验证通过后几分钟内签发。证书列表里状态变为绿色"**已签发**"，绑定 `renzhengdejuju.online` + `www.renzhengdejuju.online`，有效期 90 天。

![[Pasted image 20261104160812.png]]
> 图：证书列表——新证书"已签发"（renzhengdejuju.online + www，2026-11-04 ~ 2027-02-02），下面那个"待申请"是第一个域名卡死的废单

> 💡 复盘：同一个操作换个域名就通过了，问题大概率出在第一个域名的解析状态或控制台缓存上。**如果 DNS 验证长时间卡死，别死磕，换域名重走是最快的路**——.online 域名首年才几块钱。

## 第 8 步：WinSCP 上传证书 + Nginx 配置 HTTPS（全链路打通）

### 8.1 下载证书

在证书列表点"**下载**"，选 **Nginx** 格式，解压得到两个文件：

- `.pem` —— 证书链（公钥部分）
- `.key` —— 私钥（**绝不外泄**）

### 8.2 用 WinSCP 上传到服务器

还是第 6 步那个 WinSCP：连接服务器（SFTP / 22 / root），在服务器侧进入 `/etc/nginx/ssl/` 目录（没有就新建），把 `.pem` 和 `.key` **拖拽上传**上去。

### 8.3 配置 Nginx

编辑 `/etc/nginx/nginx.conf`（或 `/etc/nginx/conf.d/default.conf`）：80 端口全部重定向到 443，443 引入证书。

```nginx
server {
    listen 80;
    server_name renzhengdejuju.online www.renzhengdejuju.online;
    return 301 https://$host$request_uri;
}
server {
    listen 443 ssl;
    server_name renzhengdejuju.online www.renzhengdejuju.online;
    ssl_certificate /etc/nginx/ssl/renzhengdejuju.online.pem;
    ssl_certificate_key /etc/nginx/ssl/renzhengdejuju.online.key;
    # ... SSL 优化配置省略 ...
    location / {
        root /usr/share/nginx/html;
        index index.html;
    }
}
```

验证并重载：

```bash
nginx -t
systemctl restart nginx
```

### 8.4 🎉 最终验证

浏览器访问 `https://renzhengdejuju.online`——地址栏带小锁，在线考试系统页面正常显示。

![[Pasted image 20261104160838.png]]
> 图：全链路打通的最终页面——"如果你能看到这个页面，说明你的网站链路已经彻底打通！"（对比第 6 步：地址栏已经从不安全变成 https 小锁）

到这里，**从买服务器到 HTTPS 访问的闭环全部走通**。剩下的是合规（备案）和长期维护。

3. 上传材料提交初审；
4. 阿里云初审 **1~2 个工作日** → 管局审核 **1~20 个工作日**。

## ⚠️ 长期维护与避坑指南

### 1. 免费 SSL 证书只有 90 天

> 🔄 **（11-05 更新）本条已过时**：网站证书已切换为 acme.sh 自动续签（零人工），全过程见 [[07-实战记录-RAM子账号AK方案|实战记录]]。以下手动方法仅作为 acme.sh 失效时的兜底保留。

- **问题**：个人测试证书有效期 90 天，过期浏览器直接报不安全。
- **解决（手动兜底）**：手机日历定个**到期前 10 天**的闹钟。到期前重新申请一张新证书，下载替换 `/etc/nginx/ssl/` 里的旧文件，`systemctl restart nginx` 即可。

### 2. 域名是按年租赁的

- **问题**：到期不续费会被注册局收回。
- **解决**：关注阿里云续费通知及时续费；修改持有人信息后必须重新实名认证，否则被暂停解析（Serverhold）。**两个域名都要管**，不打算续的（renzhengdeju.online）到期放掉即可。

### 3. 防火墙的"双保险"

安全组放行了 80/443 但网站还是打不开？检查服务器**内部**防火墙：

```bash
# 查看防火墙状态
systemctl status firewalld
# 临时关闭防火墙（用于测试）
systemctl stop firewalld
```

### 4. 网页文件权限问题（403 Forbidden）

浏览器访问报 `403 Forbidden`，说明 Nginx 没权限读取你上传的文件：

```bash
chmod -R 755 /usr/share/nginx/html/
```
