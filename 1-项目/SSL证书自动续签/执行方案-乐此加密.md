# 乐此加密 CNAME 委派自动续签

> 整理日期：2026-11-02
> 方案类型：第三方托管 ACME 自动续签（Let's Encrypt）
> 增量费用：**约 ¥99 一次性**（买断自动续期；证书本身免费）
> 说明：文中 `ff.example.com` 是占位示例，实操时全部替换成你们的真实域名。
> 📍 **本文定位**：方案手册一（第三方托管备选路线）。阅读顺序：[[个人网站搭建|建站前传]] → [[从域名验证到证书认证-完整闭环梳理|背景原理]] → 本文 → [[备选方案-阿里云RAM角色|方案手册二]]。
> 🔄 **项目动态**：2026-11-05 已用方案手册二的简化路线（RAM 子账号 AK，见 [[实战记录-RAM子账号AK方案|实战记录]]）跑通了自动续签，本手册保留作为"续签全程不碰阿里云 API"的托管备选。

## 一、这个方案解决什么问题

**现状**：SSL 证书 90 天到期，每到期就要手动申请、下载、替换、重启 Nginx，忘了就出事故。

**目标**：装好之后，服务器上的小工具自己续证书，你不用再管。

**做法一句话**：在域名 DNS 里加一条 CNAME，把"验证域名"这件事**委派**给乐此加密（letsssl.cn）的服务器；再在服务器上装一个乐此的续期客户端。以后续期时，乐此平台替你完成 DNS 验证，客户端自动把新证书写进 Nginx 目录并重载。

**和方案二的区别**：本方案**全程不用给服务器任何阿里云 API 权限**，续期时也不登录阿里云控制台（只需首次加一条 CNAME）；代价是依赖第三方平台、自动续期要一次性付约 ¥99。方案二 0 元但更复杂，见 [[备选方案-阿里云RAM角色|方案二]]。

## 二、开工前必须懂的 5 个名词

| 名词 | 大白话解释 |
|------|-----------|
| **乐此加密（letsssl.cn）** | 第三方免费证书平台，帮你对接 Let's Encrypt，并托管"自动续期" |
| **CNAME 委派验证** | 把你域名下的 `_acme-challenge` 用 CNAME 指向乐此的服务器，CA 查验证记录时顺着这条 CNAME 去问乐此。原理见 [[从域名验证到证书认证-完整闭环梳理|背景文档]] |
| **DNS-01 验证** | Let's Encrypt 发证书前要确认"域名是你的"，方法就是查 DNS 里的 TXT 记录 |
| **续期客户端（letsssl renew）** | 装在服务器上的小工具，定期检查证书到期时间，到期自动续签、写证书文件、执行重载命令 |
| **TOKEN** | 平台生成的部署凭证，相当于密码，客户端靠它连上你的账号。**不能外泄** |

## 四、第 0 步：开工前的检查与备份

### 0.1 逐项检查前提（缺一项都做不下去）

| # | 检查项 | 怎么查 | 不满足怎么办 |
|---|---|---|---|
| 1 | 能登录乐此加密控制台 | 打开 console.letsssl.cn 登录 | 找老板要账号/注册 |
| 2 | 域名 DNS 有权限加一条 CNAME | 能登录域名所在的 DNS 控制台（本示例是阿里云） | 找管 DNS 的同事加第 3 步那条 CNAME |
| 3 | 服务器有 root/SSH 权限 | 直接登录 | 没有就没法装客户端 |
| 4 | 服务器能访问外网 | `curl -I https://letsssl.cn` | 配代理或加白名单 |
| 5 | 确定证书部署目标 | 明确哪台服务器、Nginx 是否在 Docker 里 | 先问清楚，别装错机器 |

### 0.2 备份现有证书和 Nginx 配置（必做，1 分钟，出事能救命）

**💻 在服务器上执行：**

```bash
# 创建备份目录，$(date +%F) 会自动替换成今天的日期，如 2026-11-02
mkdir -p /root/ssl-backup-$(date +%F)
# 把 Nginx 证书目录整体拷贝进去（cp -a = 连权限一起原样复制）
cp -a /etc/nginx/ssl/. /root/ssl-backup-$(date +%F)/ 2>/dev/null || true

# 备份 Nginx 站点配置
mkdir -p /root/nginx-conf-backup-$(date +%F)
cp -a /etc/nginx/conf.d/. /root/nginx-conf-backup-$(date +%F)/ 2>/dev/null || true

# 导出 Nginx 完整生效配置，留档
nginx -T > /root/nginx-full-config-$(date +%F).txt 2>/dev/null || true
```

> `2>/dev/null || true` 的意思：即使某个目录不存在报错，也不要停下来，继续往下执行。

**再记录当前证书信息（到期日等），方便之后对比：**

```bash
find /etc/nginx -type f \( -name '*.pem' -o -name '*.cer' -o -name '*.crt' \) 2>/dev/null | while read f; do
  echo "== $f"
  openssl x509 -in "$f" -noout -subject -issuer -dates 2>/dev/null
done
```

### 0.3 处理与方案二的 TXT/CNAME 冲突（关键！）

**为什么必须处理**：DNS 规定同一个名字下 CNAME 和 TXT 不能共存（原理见 [[从域名验证到证书认证-完整闭环梳理|背景文档]]）。方案二会往 `_acme-challenge.ff` 写 TXT，本方案要往同一位置写 CNAME，冲突时 CNAME 加不进去。

**💻 在服务器上先查现状：**

```bash
dig +short TXT _acme-challenge.ff.example.com
```

> `dig` = 查询 DNS 记录的命令；`+short` = 只显示结果不显示细节。

- **有输出**（说明之前写过 TXT）→ 到阿里云 DNS 控制台删掉这条 TXT → 等 10~30 分钟（TTL 生效）→ 再用上面的命令确认没输出了
- **没有输出** → 干净的，直接开工

> 删 TXT **不会**让已签发的证书立刻失效，证书会用到到期日，不用担心断网。

## 五、阶段一：乐此平台 + 阿里云 DNS（🖥️ 浏览器）

### 第 1 步：登录乐此加密

- 打开 `https://console.letsssl.cn/`（或从 `letsssl.cn` 点"登录/控制台"）。
- 用老板给的账号登录；没有账号就先注册（邮箱/手机号）。

### 第 2 步：申请证书

进入「我的证书」→「申请证书」，按下面填：

| 选项 | 建议值 |
|------|--------|
| 域名 | `ff.example.com` 和 `*.ff.example.com`（两条都加；**泛域名不包含主域名**，所以主域名要单独加） |
| CA | **Let's Encrypt**（兼容性最好，90 天） |
| 验证方式 | **DNS 验证** |
| 证书类型 | 泛域名/多域名，按实际选 |

### 第 3 步：把 CNAME 加到阿里云 DNS

提交后，平台会显示需要添加的 DNS 记录，通常是：

```
主机记录：_acme-challenge.ff
类型：CNAME
值：xxxx.cname.letsssl.cn
```

去阿里云 DNS 控制台，把这条 CNAME 加进去（TTL 填 10 分钟）。

- 加完等 10~30 分钟再继续。
- 如果平台要求的是 **TXT 而不是 CNAME**：说明这个域名没走委派模式，停下来问平台客服，不要自己乱加（会冲突）。

> **不要删除这条 CNAME。** 本方案靠它续命。删掉它，已签发的证书不会立刻失效，但以后就无法自动续期了。

### 第 4 步：等签发 + 开通自动续期

证书签发成功后：

- 进入「我的证书 → 一键部署 & 自动续期」。
- 如果提示需要开通自动续期，按控制台账单支付（约 ¥99 一次性，永久有效）。
- **支付前截图价格给老板确认**；支付后保留订单截图/发票。

### 第 5 步：生成部署命令

在同一页面填写：

| 配置项 | 示例值 | 说明 |
|--------|--------|------|
| 服务器类型 | Nginx | Apache/Tomcat/IIS 选对应项 |
| 操作系统 | Linux | |
| CPU 架构 | AMD64 或 ARM64 | 用 `uname -m` 确认：`x86_64`→AMD64，`aarch64`→ARM64 |
| 私钥文件路径 | `/etc/nginx/ssl/ff.example.com.key` | 填 Nginx 当前使用的 key 路径 |
| 证书文件路径 | `/etc/nginx/ssl/ff.example.com.cer` | 填 Nginx 当前使用的 fullchain 路径 |
| 应用重载命令 | `nginx -t && nginx -s reload` | 先 `nginx -t` 再 reload，避免坏配置直接上线 |
| 部署模式 | **Web 后台服务模式** | 可视化，推荐；CLI 模式适合脚本化 |

> 如果 Nginx 在 Docker 里：
> - reload 命令改成 `docker exec <容器名> nginx -t && docker exec <容器名> nginx -s reload`
> - 证书路径要填**宿主机上挂载给容器的目录**，否则容器里看不到新证书。

点「生成部署命令」，复制命令（里面含 `TOKEN`，**不要发到群里、不要提交到代码库**）。

## 六、阶段二：服务器装客户端（💻 SSH）

### 第 6 步：下载并检查安装脚本

不要直接 `curl | bash`，先下载看一眼：

```bash
curl -f https://letsssl.cn/download/letsssl-renew/install.sh -o /tmp/letsssl-install.sh
less /tmp/letsssl-install.sh
```

重点看：

- 下载二进制的 URL 是不是 `letsssl.cn` 域名；
- 有没有执行奇怪的系统修改；
- 安装路径是不是 `/usr/local/bin`；
- systemd 服务名是不是 `letsssl`；
- 有没有把你的 TOKEN 写到明文文件里。

确认没问题再执行。

### 第 7 步：执行安装

用平台生成的命令（把 `TOKEN` 换成你的）：

```bash
sudo TOKEN=xxxx SERVER_TYPE=nginx bash /tmp/letsssl-install.sh
```

安装完成后，终端会打印类似：

```
服务状态：active (running)
访问地址：http://<服务器IP>:8899/
首次部署认证口令：xxxxxxxx xxxxxxxx
```

记下这个一次性口令。

### 第 8 步：SSH 隧道打开管理面板并初始化

**不要把 8899 直接暴露公网。** 在你自己的电脑上建 SSH 隧道：

```bash
ssh -L 8899:127.0.0.1:8899 root@<服务器IP>
```

然后浏览器访问：

```
http://127.0.0.1:8899/
```

初始化：

1. 用终端打印的"首次部署认证口令"设置管理员密码（强密码）。
2. 登录后按提示「导入原有定时任务」。
3. 在任务列表里核对：
   - 域名是否正确；
   - 私钥路径、证书路径是否正确；
   - reload 命令是否正确；
   - 检查周期（一般每 15 天检查一次，到期前自动续）；
   - 是否开启旧证书备份。

> 如果必须远程访问 8899，至少在安全组/防火墙里只放行办公 IP。

### 第 9 步：先手动验证 reload 命令

在服务器上执行一次：

```bash
nginx -t && nginx -s reload
```

**必须成功。** 否则客户端续期后会卡在 reload 这一步。

## 七、阶段三：验证与自动化确认（💻 SSH + 🖥️）

### 第 10 步：验证证书生效

```bash
# 1. 服务状态
systemctl status letsssl --no-pager

# 2. 实时日志（Ctrl+C 退出）
journalctl -u letsssl -f

# 3. 本地证书文件内容
openssl x509 -in /etc/nginx/ssl/ff.example.com.cer -noout -subject -issuer -dates

# 4. 线上实际返回的证书（模拟浏览器连上去看服务器出示的证书）
echo | openssl s_client -connect ff.example.com:443 -servername ff.example.com 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates

# 5. HTTPS 是否正常
curl -I https://ff.example.com

# 6. 文件更新时间
stat -c '%y %n' /etc/nginx/ssl/ff.example.com.key /etc/nginx/ssl/ff.example.com.cer
```

浏览器再打开一次网站，点地址栏的小锁 → 查看证书：

- 颁发者应该是 Let's Encrypt / Google Trust Services / ZeroSSL；
- 有效期应该是新的 90 天；
- 域名包含 `ff.example.com` 和 `*.ff.example.com`。

### 第 11 步：触发一次续期检查 + 配置兜底监控

在面板里找「立即检查 / 立即续期」之类的按钮，点一次，然后看日志：

```bash
journalctl -u letsssl -f
```

观察日志是否出现：检查到期时间 → 未到期跳过（正常）→ 到期则申请新证书、写文件、执行 reload。

同时对比证书序列号/到期日有没有变化：

```bash
openssl x509 -in /etc/nginx/ssl/ff.example.com.cer -noout -serial -dates
```

> 不要反复点"立即续期"，会触发 CA 频率限制。点一次确认链路通即可。

**兜底监控**（强烈建议，自动续期也可能失败——CNAME 被误删、平台故障、网络问题）：

- **最省事**：Uptime Kuma 添加 HTTPS 监控，开启证书到期提醒（提前 20 天）。
- **最后兜底**：日历设一个到期前 15 天的提醒。
- 想自己写脚本的，见附录 12.3。

## 八、出问题了怎么办（按现象查）

| 现象 | 最可能的原因 | 处理 |
|------|-------------|------|
| 8899 打不开 | 服务没起 / 安全组没放行 / 只监听了 127.0.0.1 | `systemctl status letsssl`；用 SSH 隧道；检查防火墙 |
| 安装脚本下载失败 | 服务器不能出网 / DNS 问题 | `curl -I https://letsssl.cn`；检查代理/安全组 |
| 客户端启动失败 | 架构选错 / 权限不足 | `uname -m` 重新选 AMD64/ARM64；用 root |
| 申请证书时平台要 TXT 不是 CNAME | 该域名没走委派模式 | 停下来问平台客服，别自己加 |
| 续期失败 | CNAME 被删/改、平台账号异常、域名过期 | `dig` 查 CNAME；登录平台看证书状态 |
| 续期成功但网站还是旧证书 | reload 命令失败 / 路径不对 / Docker 没挂载 | 手动执行 reload；`nginx -T` 看实际路径；检查容器挂载 |
| Nginx reload 报错 | 配置本身有问题 | 先 `nginx -t` 看报错，修好再 reload |
| 面板密码忘了 | —— | 查官方文档/重置流程；必要时重装客户端（先备份证书） |
| 证书到期但没续 | 任务没导入 / 客户端没运行 / TOKEN 失效 | 看面板任务列表；`journalctl -u letsssl`；重新生成 TOKEN |
| 多台服务器只有一台更新 | 客户端只装了一台 | 每台终止 TLS 的服务器都装，或把证书同步过去 |

## 九、安全加固

| 项目 | 要求 |
|------|------|
| 8899 端口 | 不要暴露公网；优先 SSH 隧道；必须远程时只放行办公 IP |
| 面板密码 | 强密码，不用默认/弱口令 |
| TOKEN | 视同密码；不发群、不提交代码库 |
| 命令历史 | 安装命令含 TOKEN，执行后 `history -d` 删对应行，或命令前加空格并设 `HISTCONTROL=ignorespace` |
| 客户端权限 | 它以 root 运行，装之前确认公司安全规范允许 |
| 旧证书备份 | 保留至少一个续期周期 |
| CNAME | 不要删；删了自动续期就断 |

## 十、如何回滚 / 卸载

### 回滚（续期出问题时）

```bash
# 1. 停掉客户端，防止它继续改文件
sudo systemctl stop letsssl
sudo systemctl disable letsssl

# 2. 恢复第 0 步备份的旧证书
cp -a /root/ssl-backup-<日期>/. /etc/nginx/ssl/

# 3. 检查并重载
nginx -t && nginx -s reload
```

### 彻底卸载（确认不再使用后）

```bash
sudo systemctl stop letsssl
sudo systemctl disable letsssl
sudo rm -f /etc/systemd/system/letsssl.service
sudo systemctl daemon-reload

# 以下路径先确认再删，不要盲删
ls -l /usr/local/bin/letsencrypt-renew
ls -ld /usr/local/letsssl-data
# sudo rm -f /usr/local/bin/letsencrypt-renew
# sudo rm -rf /usr/local/letsssl-data
```

**CNAME 是否删除**：以后都不再用乐此，可以删；只是暂时停用，保留它。

**想切到方案二**：删掉 CNAME → 等 10~30 分钟生效 → 按 [[备选方案-阿里云RAM角色|方案二]] 操作。

## 十一、给老板看的一页纸

| 维度 | 乐此加密（本方案） | 阿里云 RAM + acme.sh（方案二） |
|------|------------------|------------------------------|
| 证书费用 | 免费 | 免费 |
| 自动续期费用 | 约 ¥99 一次性买断 | **0 元** |
| 续签时是否动阿里云 | 不动（首次加一条 CNAME 后就不管） | 通过 RAM 角色临时凭证自动改 DNS |
| 是否依赖第三方平台 | 是（letsssl.cn 及其客户端） | 否，全在自己手里 |
| 服务器是否存长期密码 | 存一个 TOKEN（等同密码） | **否**，每次刷工牌换临时凭证 |
| 部署难度 | 低（约 30–60 分钟） | 中高（约 2–4 小时） |
| 适合 | 想最快上线、续签完全不碰阿里云 API | 要求 0 成本、自主可控、有阿里云权限 |

**一句话**：本方案最省事，只需加一条 CNAME + 装一个客户端，续签全自动；代价是依赖乐此平台、一次性付约 ¥99。

**两条路线不能同时用**：乐此靠 CNAME、阿里云方案靠 TXT，二者在 DNS 里占同一个位置，互斥（原理见 [[从域名验证到证书认证-完整闭环梳理|背景文档]]）。

## 十二、附录

### 12.1 开工前先和老板确认

1. 乐此加密账号是谁注册的？以后用哪个账号登录？
2. 自动续期约 ¥99 一次性费用能否报销？支付方式？
3. 证书要部署到几台服务器？各自什么角色？
4. 是否有三级域名（`a.b.ff.example.com`）？泛域名 `*.ff` 不覆盖三级。
5. 公司安全规范是否允许安装第三方客户端（root 运行、开 8899 端口）？
6. 是否需要把证书同步到 CDN / SLB / WAF？
7. 变更窗口是什么时候？reload 虽然平滑，但配置错误会影响业务。

### 12.2 多服务器 / Docker / CDN

- **多台服务器**：每台终止 TLS 的服务器都装一遍客户端（推荐）；或一台签发后同步证书到其他机器（注意私钥传输安全）。
- **Docker 里的 Nginx**：证书写宿主机挂载目录 + reload 用 `docker exec`，先 `docker inspect <容器名> | grep -A5 Mounts` 确认路径映射。
- **CDN / SLB / WAF**：客户端只写本机文件，上传到 CDN 需额外脚本；有这类需求建议评估 AllinSSL / Certd。

### 12.3 到期监控脚本（可选兜底）

不想用 Uptime Kuma，就在服务器上放一个每天检查到期日的脚本：

```bash
#!/usr/bin/env bash
# /usr/local/bin/check-ssl-expiry.sh
DOMAIN="ff.example.com"
WARN_DAYS=20
WEBHOOK="https://oapi.dingtalk.com/robot/send?access_token=替换成你的"

END=$(echo | openssl s_client -connect "$DOMAIN:443" -servername "$DOMAIN" 2>/dev/null \
  | openssl x509 -noout -enddate | cut -d= -f2)
[ -z "$END" ] && exit 1

END_TS=$(date -d "$END" +%s)
NOW_TS=$(date +%s)
LEFT=$(( (END_TS - NOW_TS) / 86400 ))

if [ "$LEFT" -lt "$WARN_DAYS" ]; then
  curl -s -H 'Content-Type: application/json' \
    -d "{\"msgtype\":\"text\",\"text\":{\"content\":\"$DOMAIN 证书剩余 ${LEFT} 天，请检查乐此加密续期是否正常\"}}" \
    "$WEBHOOK"
fi
```

加 cron（每天 9:30 跑一次）：

```bash
(crontab -l 2>/dev/null; echo '30 9 * * * /usr/local/bin/check-ssl-expiry.sh') | crontab -
```
